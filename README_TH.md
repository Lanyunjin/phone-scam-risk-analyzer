# Phone Scam Risk Analyzer

Phone Scam Risk Analyzer เป็นต้นแบบเชิงวิชาการสำหรับระบุหลักฐานความเสี่ยงจาก
มิจฉาชีพในหน่วยข้อความแต่ละหน่วยที่ได้จากเสียงสนทนาทางโทรศัพท์ พัฒนาขึ้นในฐานะ
โครงงานวิทยาการคอมพิวเตอร์ระดับมหาวิทยาลัย ที่เก็บนี้เผยแพร่เพื่อการทบทวนทาง
วิชาการและแสดงผลงานเท่านั้น ไม่ใช่บริการตรวจจับการฉ้อโกงสำหรับใช้งานจริง และไม่มี
โมเดลที่ฝึกแล้วสำหรับระบบผลิตจริง

## ขอบเขต

รุ่นเผยแพร่นี้ครอบคลุมเพียงสามส่วน:

1. แนวทางออกแบบและเตรียมชุดข้อมูล
2. แนวทางพัฒนาตัวจำแนกข้อความภาษาอังกฤษแบบ multi-kernel TextCNN
3. กระบวนการ Azure Speech-to-Text สำหรับเสียงภาษาไทยที่ปลอดภัยต่อการเผยแพร่

การเชื่อมต่อแบ็กเอนด์และขั้นตอนแปลภาษายังอยู่ระหว่างพัฒนา แอปพลิเคชันมือถือไม่รวม
อยู่ในที่เก็บนี้

## กระบวนการระบบและขอบเขตภาษา

```text
เสียงภาษาไทย
  -> FFmpeg แปลงเป็น WAV 16 kHz โมโน PCM signed 16-bit
  -> Azure Speech ถอดเสียงด้วยภาษา th-TH
  -> ข้อความภาษาไทยระดับถ้อยคำพร้อมป้ายผู้พูดแบบเป็นกลาง
  -> ขอบเขตการแปลไทยเป็นอังกฤษ (การใช้งานจริงยังไม่เสร็จสมบูรณ์)
  -> หน่วยวิเคราะห์ภาษาอังกฤษ
  -> CNN ที่ใช้ GloVe แบบตรึงค่าน้ำหนัก
  -> ตัวบ่งชี้ Safe (0) หรือ Risky (1)
```

ข้อความภาษาอังกฤษที่เข้ากันได้กับการเตรียมข้อมูลของโมเดลสามารถข้ามขั้นตอนแปลได้
ยังไม่มีการเลือกหรือสร้างผู้ให้บริการแปลภาษาในที่เก็บนี้ แต่ละถ้อยคำถูกจำแนกอย่าง
อิสระ รหัสผู้พูดจาก diarization เป็นเพียงป้ายจัดกลุ่ม และไม่ระบุว่าผู้พูดคนใดเป็น
มิจฉาชีพ

## เนื้อหาในที่เก็บ

- `dataset/`: การออกแบบ นิยามป้ายกำกับ และตัวอย่างสังเคราะห์
- `stt/`: การเตรียมเสียงในเครื่องและตัวห่อ Azure ConversationTranscriber
- `model/`: สถาปัตยกรรม การเตรียมข้อความ การฝึก การประเมิน และอนุมาน
- `experiments/`: การตั้งค่าที่ผ่านการล้างข้อมูลและรายงานแบบรวมเท่านั้น
- `examples/`: อินพุตและเอาต์พุตเชิงโครงสร้างที่เป็นข้อมูลสังเคราะห์
- `docs/`: สถาปัตยกรรม วิธีวิจัย ความเป็นส่วนตัว การทำซ้ำ ข้อจำกัด และการอ้างอิง
- `tests/`: การทดสอบด้วยข้อมูลสังเคราะห์หรือข้อมูลที่สร้างชั่วคราวเท่านั้น

## การออกแบบชุดข้อมูลและป้ายกำกับ

โมเดลประมวลผลหน่วยข้อความภาษาอังกฤษทีละหน่วย:

- `0 = Safe`
- `1 = Risky`

จำนวนรวมของแต่ละชุด:

| ชุด | แถว | Safe | Risky |
|---|---:|---:|---:|
| Train | 1,164 | 605 | 559 |
| Validation | 197 | 100 | 97 |
| Test | 200 | 100 | 100 |

ไม่มีการเผยแพร่ชุดข้อมูล V9 หรือ V10 จริง และสิทธิ์การแจกจ่ายยังอยู่ระหว่างการ
ตรวจสอบ ชุด Test ถูกแยกออกจากการพัฒนาโมเดล ตัวอย่างสาธารณะไม่ได้มาจาก Train,
Validation หรือ Test ไฟล์ CSV ใน `dataset/` เป็นข้อความสมมติที่แต่งขึ้นใหม่เท่านั้น
และห้ามใช้อนุมานข้อมูลจริง

## Speech-to-Text

โมดูล STT รองรับ WAV, MP3 และ M4A ปฏิเสธเสียงที่ยาวเกินห้านาที และใช้
FFmpeg/ffprobe เพื่อสร้าง WAV 16 kHz โมโน PCM signed 16-bit Azure Speech ใช้
`ConversationTranscriber` และ `th-TH` เป็นค่าเริ่มต้น ส่งคืนส่วนข้อความแบบมี
โครงสร้าง รองรับผลสำเร็จ no-match การยกเลิก การจบเซสชัน และ timeout แบบจำกัด
โดยไม่บันทึกข้อมูลรับรอง

FFmpeg และ ffprobe เป็นโปรแกรมระบบภายนอกที่ต้องอยู่ใน `PATH` และไม่ได้ติดตั้ง
ผ่าน `pip`

## สถาปัตยกรรมตัวจำแนก

- embedding `glove-wiki-gigaword-300` ขนาด 300 และตรึงค่าน้ำหนัก
- ความยาวลำดับสูงสุด 100 เติมและตัดด้านท้าย
- Conv1D สามแขนง ตัวกรอง 64 และ kernel ขนาด 3, 4, 5
- global max pooling แต่ละแขนง แล้วเชื่อมต่อกัน
- Dense 64, dropout 0.5 และ sigmoid หนึ่งค่า
- เกณฑ์จำแนกที่ล็อกไว้: 0.14

คะแนน sigmoid ไม่ใช่ความน่าจะเป็นที่ผ่านการปรับเทียบ ผล `Risky` เป็นเพียงตัวบ่งชี้
ความเสี่ยงจากโมเดลและไม่พิสูจน์ว่าเกิดการฉ้อโกง

ที่เก็บนี้ไม่มีน้ำหนักโมเดล tokenizer ที่ fit แล้ว checkpoint หรือเวกเตอร์ GloVe
ผู้ใช้ต้องดาวน์โหลด GloVe แยกผ่าน Gensim หลังตรวจสอบเงื่อนไขของบุคคลที่สาม

## การฝึก การตรวจสอบ และการประเมิน

การพัฒนาใช้ grouped stratified cross-validation เพื่อไม่ให้กลุ่มที่เกี่ยวข้องกัน
ข้ามขอบเขต fold tokenizer และเมทริกซ์ embedding ถูกสร้างภายในข้อมูลฝึกของแต่ละ
fold เครื่องมือสาธารณะรายงานเฉพาะค่าสรุปและไม่เขียนข้อความจริง OOF prediction
หรือรายงานข้อผิดพลาดรายแถวโดยปริยาย

เลือกเกณฑ์จำแนกก่อนประเมิน Test โดย Test ไม่ถูกใช้ในการฝึก เลือกสถาปัตยกรรม หรือ
เลือกเกณฑ์ ผลรวมที่อนุมัติสำหรับตัวจำแนกข้อความคือ:

| แถว | เกณฑ์ | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---:|---:|---:|---:|---:|---:|---:|
| 200 | 0.14 | 0.9400 | 0.9314 | 0.9500 | 0.9406 | 0.9871 |

ค่านี้เป็นผลของตัวจำแนกข้อความเท่านั้น ไม่ใช่ผลของระบบเสียง การถอดเสียง การแปล
แบ็กเอนด์ หรือแอปมือถือแบบครบวงจร ประสิทธิภาพในโลกจริงอาจแตกต่างออกไป

## การติดตั้งและการตั้งค่า

แนะนำ Python 3.11 หรือ 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

ติดตั้ง FFmpeg แยกต่างหาก และให้ `ffmpeg` กับ `ffprobe` อยู่ใน `PATH`

```powershell
Copy-Item .env.example .env
$env:AZURE_SPEECH_KEY = "your-own-key"
$env:AZURE_SPEECH_REGION = "eastasia"
```

โค้ดอ่าน environment variables โดยตรงและไม่อ่าน `.env` อัตโนมัติ ห้าม commit
ไฟล์ `.env` จริง

## การตรวจสอบและตัวอย่างที่ปลอดภัย

การทดสอบไม่เรียก Azure ไม่ฝึกโมเดล ไม่ดาวน์โหลด GloVe และไม่ใช้ artifact ส่วนตัว:

```powershell
python -m pytest tests
python -m json.tool examples/synthetic_transcript.json
python -m json.tool experiments/reports/v10_final_test_aggregate.json
```

ตัวอย่าง JSON และ CSV เป็นข้อมูลสังเคราะห์และไม่เคยใช้ฝึกหรือประเมินโมเดล

## ความเป็นส่วนตัวและข้อจำกัด

- ไม่มีชุดข้อมูลจริง เสียงจริง แถว Test prediction รายแถว โมเดลที่ฝึกแล้ว tokenizer
  ที่ fit แล้ว หรือไฟล์ GloVe เต็มชุด
- ความผิดพลาดจากการถอดเสียงและการแปลอาจส่งต่อไปยังการจำแนก
- การเชื่อมต่อการแปลภาษายังไม่เสร็จสมบูรณ์
- แต่ละถ้อยคำถูกจำแนกโดยไม่มีบริบทการสนทนาทั้งหมด
- รหัสผู้พูดไม่ระบุว่าใครเป็นมิจฉาชีพ
- ผลลัพธ์ไม่ใช่คำตัดสินทางกฎหมาย การเงิน หรือความปลอดภัย
- ประสิทธิภาพอาจเปลี่ยนตามผู้พูด โดเมน สำเนียง อุปกรณ์ เสียงรบกวน และรูปแบบภาษา

ดู `docs/privacy_and_data_handling.md` และ `docs/limitations.md`
